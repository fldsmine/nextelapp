# Nextel Android → Flutter Migration Assessment

**Scope:** repository inspection plus incremental implementation notes. Flutter migration work is in progress on `arena/9171df30-nextelapp`; this document is a roadmap, not a claim of release verification. Native Kotlin screens remain in the repository until Flutter parity is verified.

## 1. Existing application architecture

- The source product is a native Android app using Kotlin and some Java, XML layouts, View/Data Binding, AndroidX, and Material Components. It is **not** Jetpack Compose. A Flutter project now lives under `flutter/` alongside the retained Android implementation.
- App identity is `pynith.apps.nextel` / **Nextel**. Android config is min SDK 23, target SDK 34, compile SDK 36, version `3.5.alpha` / code 4, with debug and release build types and no product flavors.
- The original native user journey was: animated splash → login/register/verification/reset → bearer-token validation → `web-session` API handoff → authenticated Laravel/Livewire dashboard in Android `WebView`.
- The repository does **not** contain the Laravel backend or the Livewire dashboard source. The dashboard, profile, and VAS/feature pages are remote web pages; native reconstruction of those pages cannot be derived from this checkout. The parity-preserving default is to keep that dashboard in a Flutter WebView and migrate the Android-owned screens and bridge behavior.
- There is a central OkHttp JSON client and helper/service classes, but no consistent ViewModel/repository/domain layering. UI and state live mostly in Activities; the three games have separate rule/controller classes.

## 3. API, auth, persistence and device-function inventory

- **API contract:** OkHttp sends JSON, `Accept: application/json`, optional Bearer token, parses `{success,message,data,errors}`, field errors and `Retry-After`. Endpoints found: `login`, `user`, `register`, `countries`, `email/verify`, `email/resend`, `password/forgot`, `password/reset`, `web-session`, `logout`, `support-tickets` (+ ticket/messages), `coupons/verify`. Update feed is separately queried at `/api/v1/app-upgrade`.
- **Web session:** `web-session` returns a same-origin redirect and `Set-Cookie` values. The app installs an `app_gate` cookie, validates the destination host, writes cookies into Android `CookieManager`, and shares that store with WebView and the OkHttp `WebCookieJar`. Logout clears cookies/WebStorage, queues the token in encrypted Flutter storage, and mirrors it into an AES-GCM/Android-Keystore queue consumed by network-constrained WorkManager when offline.
- **Persistence:** the pre-existing Android app has no Room/SQLite database; the uploaded Flutter game source uses `shared_preferences` key `game_history` for Dice and `scores_database.db` for Hangman. The integrated Flutter games preserve those source formats and perform a one-time compatibility import from `games.dice.history.v1` and `games.hangman.scores.v1`, which the app's `LegacyDataMigrator` copies before routes open. Imported histories/scores are not removed from the legacy preference store. Import behavior is covered by Dart parser tests but has not been exercised on an installed device. Active tokens and the foreground logout queue use `flutter_secure_storage`; the WorkManager mirror is encrypted per token with AES-GCM and an Android-Keystore key. Settings use named `SharedPreferences`; WebView cookies/DOM storage are separate. Canvas images, camera temp files and downloaded APKs use app/external storage or MediaStore.
- **Permissions/native behavior:** Internet/network, legacy storage (limited to old Android versions), notification posting, exact alarms, unknown-package install, and biometric permission. Camera/gallery are launched through Android intents. App has no declared app-link/deep-link filters beyond launcher.
- **Notifications/background:** the Flutter module schedules exact reminders for 08:00, 15:00 and 19:07 in `Africa/Lagos`, creates notification channels, restores alarms after boot and reschedules them after firing; cancellation is limited to its own alarms/notifications. WorkManager runs the connected-network 24-hour update check and network-constrained encrypted logout-revocation retries. APK installation uses the Flutter module's narrow Kotlin/FileProvider bridge. Exact-alarm, reminder delivery, WorkManager, installer, cookie and Keystore behavior still require device verification.

## 5. Recommended Flutter shape

The current app follows a feature-first structure with `flutter_riverpod`, `go_router`, Dio repositories, `flutter_secure_storage`, and `flutter_inappwebview`. Keep domain logic (validation, coupon mapping, game rules and update state) out of widgets and cover it with Dart unit tests. Preserve the application ID, assets/fonts and stored user data. Keep native Kotlin limited to Android-specific migration/bridging that packages cannot safely reproduce (legacy Keystore/preferences import, shared `CookieManager`, exact reminders, background WorkManager retries and APK installation).

## 6. Risks, assumptions and items to verify before release

1. **Dashboard source is absent.** Flutter can preserve the hosted Livewire UI, but pixel-level/native recreation of it requires the separate Laravel/frontend repository and backend contract.
2. **Existing-install continuity is implemented but unverified on a device.** The one-time importer migrates named settings, game histories, the Keystore session and queued revocations without clearing source data until the Flutter copy succeeds. Upgrade testing must still confirm real installed-user cookies and token recovery.
3. **Credential handling changed; verify upgrade behavior.** The Flutter login flow never persists the account password; biometric auth gates a remembered encrypted token. The Flutter bridge deletes legacy plaintext username/password preference keys at startup, but installed-device migration and the retained legacy Kotlin client still need review.
4. **Release signing is environment-only; release verification is pending.** Both Gradle application modules have no source fallback for signing material and only attach a release signing config when all four protected inputs are supplied. Build and signing still need CI/local verification.
5. **Backend endpoint ownership must be confirmed.** Debug defaults now match the README. The legacy update-feed host remains deliberately independent and is configurable with `NEXTEL_UPDATE_API_BASE_URL` / `nextelUpdateApiBaseUrl`; the backend owner must confirm the staging and production feed values before release.
6. **Reminder implementation is present; device behavior remains unverified.** The Flutter module creates channels, restores after boot, self-reschedules the 08:00/15:00/19:07 `Africa/Lagos` alarms, and cancels only its reminder alarms/notifications. Verify exact-alarm permission and delivery on supported Android versions.
7. **The `app_gate` cookie's backend security model remains an owner decision.** The Flutter module has no source fallback and reads only the protected `NEXTEL_APP_GATE_COOKIE` build input; it never exposes the value to Dart/JavaScript. Confirm its purpose, issuance and rotation policy before release.
8. **Legacy Kotlin cleanup remains a separate owner decision.** Reachability checks found no callers for `WebTimeline` or `generateQrCode`; `StoreActivity` is manifest-only, `NoticeActivity` is neither declared nor called, and the duplicate `SettingsActivity` has no callers (`HomeActivity` uses `AppSettingsActivity`). Firebase config has no SDK/plugin consumer. The old source/config are retained to avoid deleting legacy app material in the Flutter migration PR.

## 7. Baseline verification

The Flutter test suite includes migration tests for auth validation, API failures, bridge parsing, Support, Coupon, settings models, About/FAQ, Games persistence/imports, updater behavior, background-result handoff and cached-build invalidation; native-bridge tests cover the strong-biometric availability/prompt calls and enqueueing/removing logout tokens. Android's Keystore encryption and WorkManager execution still require instrumented/device validation. The previous Kotlin Games port and its JVM-only tests are removed from this PR. This environment has no Flutter/Dart executable, Java, Gradle executable, Android SDK or ADB on `PATH`, so Flutter analyze/test/build, Android Gradle tasks and device/installer verification could not run. Install/configure the toolchains before claiming a verified build or device migration.
